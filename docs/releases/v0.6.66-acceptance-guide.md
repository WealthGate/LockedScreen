# LockedScreen 0.6.66 Acceptance Guide

Use `tmp/LockedScreen-0.6.66-Test.lnk` on the build PC; no GitHub download is needed.
The shortcut uses a separate profile, not the installed production app's data.
Use only a practice assessment and have the configured invigilator PIN available.
The app will not open or weaken an exam session automatically for these tests.

## Google Forms

1. In Teacher, create a linked/hosted exam using your practice Form's responder link.
   Retain Google's Limit to 1 response and any required account/domain restrictions.
   Do not use an edit link. Export/import the package if testing a student PC.
2. Set and retain the invigilator exit PIN. Check native companion readiness and
   use Full Kiosk Mode. Start the practice session under supervision.
3. Click the Form's Sign in button. Expect Google's sign-in page inside the same
   locked view, not the previous blanket unsupported-browser notice. Your practice
   short link's public redirect/email-entry step was checked without credentials.
4. Manually enter your own practice account credentials and complete required 2FA.
   Never send credentials, codes, cookies or tokens to the assistant. Confirm the
   browser returns to the same Form and Google shows the intended account.
5. Verify fullscreen and switching restrictions remain active throughout. Try wrong
   and correct exit PINs in separate practice runs. No successful sign-in should
   itself release lockdown or expose the desktop.
6. Submit a practice response inside Google Forms and check Google's confirmation.
   Record online submission then saves the separate local session record. With a
   configured Classroom binding, verify session-report delivery without overwriting
   Forms-managed marks. Google owns the form answers, response limit and grade.
7. Reopen the same Form with the same account in a separate supervised run. Confirm
   Google enforces the existing one-response restriction. LockedScreen does not
   implement or replace Google's server-side response limit.

If Google's own page rejects the browser/account, record the exact visible error
without credentials. Do not disable response limits or spoof the browser to pass.
A successful email-entry landing page does not establish post-credential compatibility.
For school SAML/SSO redirects, have the administrator approve only the required
identity-provider paths in the package before retrying; unrelated browsing stays denied.

## Regression Tests

Repeat the 0.6.65 local record confirmation/cancel, save error/retry, expiry/retry,
delivery failure/retry, protected return/restart without timer reset, and PIN-only
exit checks. Confirm Search, mailbox, Drive, account settings and another Form cannot
be reached through a sign-in continuation or a broad legacy Google domain rule.

Also repeat a native exam: Classroom consent before lockdown, questions only after
protection is ready, automatic configured delivery after submission without release,
and final PIN-only exit. Across-PC native grade passback still needs teacher authority.

Test actual display scale, touch/IME/accessibility and target-PC recovery under
supervision. Unmanaged Windows cannot guarantee suppression of reserved secure-
attention keys or privileged tampering. WACK does not test those guarantees.

Complete the same checks through a signed private Microsoft Store flight before
public Store submission. This release does not promise every site or every SSO flow.
