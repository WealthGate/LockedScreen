# 0.6.62 Validation Record

Date: 2026-11-18. This is a supervised-test candidate, not a claim of Microsoft
certification, penetration-test completion, or absolute Windows lockdown.

## Automated Checks

- TypeScript typecheck: passed with Node 24.22.3.
- Desktop, document-import and storage tests: 52 passed, none skipped or failed.
  Includes the asynchronous-operation startup barrier, active-session IPC,
  invigilator PINs, submission identity, native readiness, cleanup and recovery.
- Native keyboard policy: 108 assertions passed under .NET 10; no hooks activated.
- Hosted OAuth service: 8 tests passed. The hosted service stays at 0.6.61; the
  desktop protocol remains compatible and does not require a service redeployment.
- Browser UI at 1360px and 390px: active routing, rejected wrong PIN, masked PIN,
  security hold and correct release passed using mock IPC. These are not OS tests.
- Teacher, Student and combined Store archives are smoke-tested in Electron with
  isolated fictional data. Physical lockdown and external launches are disabled in
  that harness. Teacher/Store import both typed and scanned PDFs; Student refuses
  teacher authoring. A foreign browser frame cannot access the application IPC.

## Runtime And Supply Chain

- Bundled Electron: 45.3.4, with Node 24.22.3.
- Self-contained native runtime: .NET 10.0.15, built using SDK 10.0.404.
- PDF.js 6.5.438 and native canvas 1.1.1 replace the duplicate legacy PDF engine.
- Desktop production npm audit: zero reported vulnerabilities.
- Hosted OAuth production npm audit: zero reported vulnerabilities.
- Native service including transitive NuGet packages: no reported vulnerabilities.
- The full development dependency tree still reports 19 advisories (14 high,
  5 moderate), including build-time globbing/tool dependencies. They are not
  silently waived or fixed with incompatible forced dependency replacements.
  Vite, electron-builder, minimatch, picomatch and pdf-parse are absent from the
  packaged application archives. Build inputs still require publisher trust.
- Production EXE fuses disable RunAsNode, NODE_OPTIONS and Node inspection; enable
  cookie encryption, embedded ASAR integrity and loading only from app.asar.
- Known publisher Web OAuth secret and hosted token-encryption key are absent
  from all three desktop archives and changed source files. No embedded Google
  client-secret prefix was found. Public client IDs are not confidential.
- Student payload excludes document-authoring parsers/OCR. All three builds carry
  the same native helper binaries. The APPX archive must match the tested Store
  unpacked archive before release.

   Confirm the publisher Google project's External/In production state and Google

   this local validation. School Workspace app-access policies also still apply.
4. Validate managed Windows policy for reserved keys, secure desktop, touch,
   accessibility/IME, multiple users and privileged tampering. A user-mode agent
   cannot guarantee these controls on an unmanaged Home/Pro device.
5. Use a private Store package flight before general publication. GitHub installers
   are unsigned validation downloads and can show Windows reputation warnings;
   they are not a substitute for Store signing/certification.
