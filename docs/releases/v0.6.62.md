# LockedScreen 0.6.62

Status: supervised-test prerelease, not the stable automatic-update release.

Security hardening for active examinations in the combined Microsoft Store build
and the GitHub Student/Teacher installers. No Google publisher secret is added to
any desktop artifact. Hosted OAuth remains the default Google connection.

For GitHub testing, download `LockedScreen-Setup-0.6.62-x64.exe`. It downloads only
the selected Student or Teacher installer. These EXE files are unsigned and may
show Windows reputation warnings. The Store APPX is prepared separately for
publisher submission and Store signing, not installed by this download chooser.

## Active Exam Changes

- Main-process PIN enforcement applies to every active exam, including a teacher
  taking a test in the combined build. An exported package's PIN verifier takes
  precedence over the receiving teacher device's own PIN.
- Active exam routing cannot be replaced by Teacher, Student portal, import, or
  other launch-context views. Unmounting a page no longer releases lockdown.
- A deny-by-default active-session IPC policy blocks authoring/settings changes,
  external browser/help launches, file dialogs, external applications, screenshot
  export, and changes to kiosk/navigation controls. IPC requires the trusted main
  window's top-level frame.
- Store update links use the same authorization and cannot open Microsoft Store
  during an exam. Update notifications/installations are held during transitions.
- Exam startup waits for earlier asynchronous sign-ins, file dialogs, imports and
  turn-in operations to finish, preventing a pending browser/dialog from appearing
  after lockdown begins.
- Hosted navigation is enforced at network-request level, including redirects and
  programmatic webview changes. Google asset origins do not grant general browsing.
  Prefix rules compare parsed origins/paths, and hosted frames cannot acquire Node
  integration, a preload bridge, insecure content, or nested webviews.
- Native startup is mandatory for real exam routes, regardless of the diagnostic
  profile's native-verification checkbox. No fullscreen-only fallback is used.
  Questions and the hosted exam are not shown until startup succeeds.
- Kiosk mode disables window minimization, movement and resizing, protects content
  capture, and reclaims focus. Normal window controls are restored after release.
- Native keyboard filtering runs on its own message-loop thread with event-based
  modifier tracking and matching blocked key-up/repeat handling. The callback does
  no logging, disk I/O, process enumeration, or asynchronous key-state queries.
- Agent status requires a live matching executable/process start time, fresh
  heartbeat, ready keyboard thread, and matching randomized exam session ID.
  A periodic failed health check or display-count change pauses the exam without
  silently releasing it. Starting with multiple displays is refused.
- Startup refuses a Windows key already held before the native filter starts;
  release the key and retry. A key-down already delivered to Windows must not be
  carried into a newly locked exam.
- Submission does not unlock the device. LMS sign-in/turn-in starts only after
  the current session's submission is saved and a valid invigilator PIN releases
  the device. Approved external applications are not available inside strict exams.

## Runtime And Dependencies

- Electron is updated from 36.0.0 to 45.3.4. Developer builds and CI require Node 24;
  end users do not install Node separately.
- Native helpers move from the end-of-support .NET 8 runtime to .NET 10 LTS.
  Builds require the .NET 10 SDK; installed helpers remain self-contained.
- The sanitizer, updater, router, math renderer, XML parser and PDF engine receive
  security updates. The duplicate legacy PDF parser is removed; typed PDF and OCR
  use the maintained PDF.js engine without enabling PDF scripting or XFA forms.
- Release fuses disable Node-mode startup, NODE_OPTIONS and inspector arguments,
  enable cookie encryption and embedded ASAR integrity validation, and require the
  application archive instead of loading a substituted application directory.
- A clean production-dependency audit is not proof of complete application security.
  Build-only advisories and device-level/live test results are recorded separately.

## Scope And Limits

These are application/native-agent protections, not a guarantee that an ordinary
desktop application controls every Windows-reserved action. In particular,
Ctrl+Alt+Delete, secure desktop/UAC, power controls, privileged software, hardware
actions, other users, touch/accessibility surfaces and local-administrator tampering
require school-managed Windows configuration and deployment testing. A same-user
native agent is not an administrator-resistant security boundary.

Microsoft Keyboard Filter can suppress reserved combinations and supports Windows
Education, Enterprise and IoT Enterprise, not Home/Pro. Enabling it requires device
administration and restart. This release does not enable it or change Windows
security/accessibility settings automatically.

The combined Store package still contains both workspaces. Selecting Student on its
welcome page is not a permanent OS-enforced Student installation. This hardening
prevents leaving an **active exam**, not access to Teacher tools on an unlocked
shared teacher installation. Use the restricted Student installer or a separately
managed student account for devices that must never expose teacher authoring.
