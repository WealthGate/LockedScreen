# LockedScreen 0.6.61 Acceptance Test

Do these tests with practice exams and test Google accounts/classes, not a live examination.
The local test shortcut runs the same application files used in the Store APPX with a
separate workspace. It is not a Store-installed identity, installation, or update test.
Do not double-click the unsigned Store APPX expecting a normal local installation.

## 1. Open the Separate Test Copy

1. Save other work and close all existing LockedScreen windows normally. Do not uninstall
   or delete the current Store installation or its data.
2. Open `tmp/LockedScreen-0.6.61-Test.lnk`. It starts
   `apps/desktop/dist-store/win-unpacked/Lockedscreen.exe` with a separate
   `--user-data-dir` pointing at `tmp/acceptance-0.6.61`.
3. Check that the footer says 0.6.61. Choose **Teacher / School**. A fresh workspace
   may contain a sample exam; it should not contain your existing real submissions.
4. In **Admin Console > Controls**, set and remember a private test invigilator PIN,
   then **Save settings**. The fresh default is 2468, but do not use the default for
   a real deployment or send your chosen PIN in chat.

The separate data-directory behavior was checked with Electron 36 before preparing
the shortcut. The shortcut does not install software or alter Windows certificate trust.

The current combined Store candidate defaults to full Teacher access and offers a
Student **view**. Choosing that view does not persist a permission-enforced Student-only
installation role. This walkthrough can test exam lockdown, but it must not be treated
as proof that a student cannot later enter the Teacher workspace outside the session.
If permanent Student-only access is required for this single-package Store release,
hold that rollout until the role selection is persisted and enforced in the main process.

## 2. Test Real Teacher Google Sign-In First

1. Open **Admin Console > Google Classroom**. Google Classroom should be enabled.
2. New installations default to the publisher-managed provider. If you need to inspect
   it, unlock **Advanced admin Google setup** with your test admin PIN and confirm
   **Google connection provider > LockedScreen publisher-managed**. Save settings
   if changed. Do not paste a Google client secret into the app.
3. Under **LMS connections**, select **Connect Google Classroom**. The system browser
   should open through `auth.whsdominica.com` to Google's sign-in/consent page at
   `accounts.google.com`. Sign in with the teacher Google account for your practice class.
4. Review the requested permissions. If Google says the app is blocked, unverified,
   or restricted by school policy, stop and record the exact message. Do not bypass
   Google or school restrictions. Never send a callback URL, token, secret, or password.
5. Return to LockedScreen. Confirm the correct teacher name/email and load classes.
6. Close the app normally, reopen the test shortcut, and load classes again. This checks
   session persistence. Repeat class loading after more than one hour to check token
   refresh; do not change the Windows clock to simulate expiry.

Pass: no school OAuth project/secret entry is required, and the correct teacher's
practice classes load. A service health check alone is not a sign-in pass.

## 3. Post a Practice Exam and Verify the Assignment ID

1. Create a short app-based exam with three multiple-choice questions and known answers.
   Name it **LockedScreen 0.6.61 Practice** and save it.
2. In **Admin Console > Overview**, select its configuration package and
   **LMS / grade integrations**.
3. Open **Student turn-in**. Enable post-submit LMS turn-in, choose **Google Classroom**,
   your connected teacher account, and the practice class. Use **Load classes** if needed.
4. Select **Post package to class**. After success, confirm the Classroom assignment ID
   is populated and the selected class is still correct. Save the package.
5. Open [Google Classroom](https://classroom.google.com/), then the practice class's
   **Classwork**. Confirm the assignment appears once and contains the `.lscp` attachment.
6. Export the saved package to a local practice folder. Do not share an old export from
   before the assignment was created: the distributed file must carry the assignment ID.

Pass: posting succeeds, the ID is retained, the attachment opens, and local export succeeds.
Before retrying a failed post, check Classroom and Drive for a partially created item
so the test does not create accidental duplicates.

## 4. Configure and Check the Real Native Lockdown Path

Do not begin until you know the correct release PIN and have saved other work.
Keep this checklist available separately; a working lock may prevent returning to chat.

1. Select the practice package in the Admin Console. Under **Package basics**, set
   **Security level > Full Kiosk Mode** and **Save package**.
2. Under **Student access**, set a practice **Exam start code**, save, and re-export.
   This code is different from the invigilator exit PIN.
3. Under **Runtime**, leave **Allow student exit immediately after submit** off and
   **Require invigilator PIN to leave after submit** on. Save the package.
4. Select **Refresh diagnostics**. The native companion must report status checks passed
   and be lockdown-capable, not merely partial/present. Inspect **Security** and choose
   **Native Windows companion** as deployment mechanism when that is the actual setup.
   Record **Native Windows lockdown companion is installed and verified** only after
   the native checks and your supervised deployment test substantiate it; **Save posture**.
5. Do not mark an official Windows kiosk deployment or dedicated exam account as configured
   unless it actually exists. Do not count **Launch testing session**, Windows Home
   fallback/testing mode, or Electron window assist alone as a successful full lock.
6. Use the app's Student view with the fresh exported practice package. Verify a wrong
   exam start code is rejected, then start with the correct one.
7. While the exam is active, manually test the configured restricted shortcuts, including
   Alt+Tab, Alt+F4, the Windows key/Win+D, and Ctrl+Shift+Esc. Record each as blocked or escaped.
   Confirm that ordinary exam answering still works.

Pass: restrictions are genuinely enforced rather than reported only as advisory, and
no external Google browser opens during the exam. Native exam lock is not a guarantee
against every Windows secure-desktop, administrator, hardware, or recovery control.

## 5. Submit, Reject Wrong PINs, Then Release and Turn In

1. Answer two of the three questions correctly, then submit. Confirm the saved local
   score is 2/3 and the app remains locked. Do not begin Google sign-in yet.
2. Try a wrong invigilator PIN with the release control. It must not release the session.
3. In the new Google turn-in panel, try a wrong PIN with **Turn in to LMS**. It must not
   open an external browser or release the exam. An empty PIN must not start that action.
4. Enter the correct invigilator PIN into **Invigilator PIN for release and Google turn-in**
   and choose **Turn in to LMS**. This deliberately releases the saved exam session first,
   then opens Google in the system browser. It is not a Google window inside a still-locked exam.
5. Sign in as a practice student enrolled in the selected class, not as the teacher.
   Return to the app and check the turn-in status. In Classroom, verify the report/turn-in
   belongs to that student and the expected assignment.
6. On this same test workspace, with the teacher connection still available, check the
   reported grade-sync status and Classroom grade. If the assignment uses a different
   maximum score, verify the equivalent scaled grade rather than expecting literal 2/3.
7. After authorized release, confirm normal task switching, Windows/taskbar behavior,
   and normal app closing have returned. Reopen the test copy and verify the saved answers,
   score, and delivery state in **Results**.

If the correct PIN cannot release the app, stop acceptance testing and report the release
failure. Do not run another lockdown test until the release path is understood.

## 6. Negative Cases and Another PC

1. Cancel a Google sign-in once. Confirm the app reports failure/cancellation without
   losing the saved exam submission; retry and complete sign-in.
2. Reopen the exported exam and verify its start-code requirement still applies. Keep
   teacher-only account/session credentials out of student packages.
3. On another PC, use the candidate's Student workflow and the fresh exported package
   with a practice student account. Confirm exam access, native restrictions, correct-PIN
   release, report upload and assignment turn-in independently.
4. **Cross-device grades are a separate check.** A different student's PC has no teacher
   OAuth vault. Automatic teacher-authorized grade writing there requires the configured,
   authenticated grade-sync bridge described in `docs/server-grade-sync.md`. Hosted OAuth
   by itself does not implement that bridge. Do not count same-PC grade success as proof
   that grades from every student's PC will sync automatically.

## 7. Verify the Actual Store-Installed Package Before General Release

After local app-code checks pass, use **Partner Center > LockedScreen > Package flights >
New package flight**. Add only your tester Microsoft accounts, upload
`apps/desktop/dist-store/LockedScreen-Store-0.6.61-x64.appx`, attach the reviewer instructions,
and submit that limited flight for certification. Once approved, install/update through
Microsoft Store while signed into an included tester account, then repeat the checklist.
The existing public package remains available to customers outside that flight.

Package flight documentation:
https://learn.microsoft.com/en-us/windows/apps/publish/package-flights

This checks Store installation, package identity, packaged helper paths, and the
Store-managed update path that the unpacked test shortcut cannot prove. Do not merge
or publish an automatic general installer update as a substitute for this Store test.
Review the optional WACK blocked-executable finding before a general-release submission.
