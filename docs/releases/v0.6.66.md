# LockedScreen 0.6.66

Supervised-test candidate restoring website sign-in inside the locked exam browser.
This corrects the app-side Google Forms sign-in regression; full Google account
authentication and return to the form still require manual acceptance testing.

LockedScreen previously permitted website sign-in in commit `b966d78`. Later
hardening reintroduced a blanket block on Google account pages. The message shown
by 0.6.65 was generated by LockedScreen before Google could evaluate the sign-in.
That was not evidence that Google had rejected this particular form.

Safe Exam Browser for Windows also uses embedded Chromium via CefSharp/CEF,
with separate kiosk enforcement and URL filtering, not an ordinary unrestricted
Chrome window. See [SEB's technical details](https://safeexambrowser.org/about_overview_en.html)
and [request handler](https://github.com/SafeExamBrowser/seb-win-refactoring/blob/master/SafeExamBrowser.Browser/Handlers/RequestHandler.cs).
This update adapts the controlled-navigation approach to LockedScreen's existing
Electron engine; it does not copy or bundle SEB or impersonate it.

- Google website sign-in and password/2FA challenge navigation stay in the same
  locked webview, with a checked return to the configured exam.
- Forms short links bind to the resolved form. Other forms, Search, Gmail, Drive,
  account settings and unrelated Google browsing remain blocked, even with broad
  legacy Google domain lists in a Forms package.
- Approved assessment-site OAuth is identity-only and bound to that assessment's
  origin. Publisher API OAuth stays in the existing pre-exam hosted flow; its
  callbacks and API scopes are not permitted as website-login exceptions.
- Approved popup navigation is contained in the existing exam view. No unrestricted
  external browser, additional PC workspace, cookie copying or credential automation
  is introduced. Sandbox/isolation, native fullscreen and exit-PIN enforcement remain.
- The stale Chrome 124 user-agent override is removed. The engine uses its genuine,
  current Electron identity instead of masquerading as Chrome, Firefox or SEB.
- The UI distinguishes sign-in progress, an app-policy block and a rejection
  actually returned by Google. Session recording is disabled during sign-in.
- The 0.6.65 local-record feedback/retries and provider-grade protections remain.

The supplied practice Form was tested through its short-link redirect, canonical
Form and `/Login` to `/v3/signin/identifier`. Google's email-entry field rendered
with the default Electron identity and the scoped policy. No Google credentials,
consent or exam answers were entered; temporary probe cookies were cleared.
This is a landing-page/redirect test, not proof of successful account authentication.

Keep Limit to 1 response enabled. Google and school identity policies still decide
whether to accept a browser/account; [Google documents embedded-browser restrictions](https://support.google.com/accounts/answer/7675428).
Do not claim universal website or Google sign-in compatibility from this change.
Schools using external SAML identity providers must approve their specific routes;
an unrestricted identity-provider domain exception is not added automatically.

Use the new local test shortcut or GitHub test installers. The combined Store APPX
is a test candidate, not certification approval. Stable updates and the public Store
submission remain unchanged until full acceptance.

See [acceptance guide](https://github.com/WealthGate/LockedScreen/blob/codex/student-teacher-editions/docs/releases/v0.6.66-acceptance-guide.md),

Blocked executables failure and 238 .NET analyzer warnings remain disclosed in the
validation record. Independent Windows CI and archived-payload checks passed. Full
manual sign-in, response-limit enforcement and supervised lockdown remain required
before public Microsoft Store submission.
