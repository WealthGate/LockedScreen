# LockedScreen 0.6.65 Reviewer Instructions

LockedScreen provides native exam authoring and a student examination runtime.
The combined Windows package offers Teacher and Student workspaces. Use a practice
assessment on an isolated test PC, with the invigilator PIN set before starting.
Do not begin a locked session without knowing its configured exit PIN.

Teacher Google connection uses the publisher-hosted OAuth service. Teachers sign
in with their own Google account; schools do not need to create an OAuth project
for this default connection. School administrators may still require approval
under their Google Workspace app-access policies. No publisher Web client secret
or teacher refresh token is embedded in student packages.

For a native exam with configured LMS turn-in, student authorization finishes in
the external browser before lockdown starts. Submit saves the local result and
attempts delivery without another browser or PIN. Missing authorization fails
closed. The invigilator PIN is required to exit, including after submission.
Cross-device numeric grade passback requires a teacher-authorized grade service.

For compatible linked forms, submit inside the provider's page first. Record online
submission then opens an in-app confirmation and saves a local session record.
It is not proof that Google received answers, and does not contain provider marks.
Configured LMS delivery sends the session report without overwriting provider grades.
Return/restart confirmations preserve the exam timer. Save/delivery failures have
visible retry controls and do not unlock the session.

Signed-in Google Forms, including Limit to 1 response, are not supported inside
the embedded browser. Classroom OAuth does not create a Forms website session.
This update retains that security restriction rather than opening an unrestricted
browser during exams. No claim of signed-in Forms support should be made.
