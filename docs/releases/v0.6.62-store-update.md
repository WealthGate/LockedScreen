# 0.6.62 Store Update

## Test First

1. Check `v0.6.62-validation.md`, including final artifact hash and WACK findings.
   Do not upload an older intermediate APPX or call a WACK result certification.
2. Use the isolated `tmp/LockedScreen-0.6.62-Test.lnk` for a supervised practice
   test without replacing the installed Store app. This tests the same application
   files, but does not test Store identity or signed installation.
3. Follow `v0.6.62-acceptance-guide.md` with a known, non-default invigilator PIN.
   Use spare/test devices, not an unsupervised live student examination.

## Signed Store Test

1. Sign into Partner Center and open the existing LockedScreen product. Keep its
   registered identity; do not create another product or change the publisher.
2. In the product overview, choose **New package flight** and create/select a known
   tester group containing your and the other teacher's Microsoft Store accounts.
3. Open the flight's **Packages** section and upload
   `apps/desktop/dist-store/LockedScreen-Store-0.6.62-x64.appx`.
   Expected identity: `WealthGate.LockedScreen`, version `0.6.62.0`, x64.
4. Add `v0.6.62-reviewer-instructions.md` under additional testing information.
   Confirm the listing privacy URL is `https://auth.whsdominica.com/privacy`.
   Resolve Partner Center errors/findings and submit the flight for certification.
5. After flight approval/publication, sign into Microsoft Store with each tester's
   included account and check Library updates. Verify 0.6.62 and repeat the
   supervised checks on that signed installation.

Flight certification is still required. Microsoft can require corrections even
when a local WACK run passes. Other customers remain on the regular submission.

## General Release

After signed-device acceptance, create an update to the existing public Store
submission using the same validated package. Review listing/privacy, reviewer
instructions and warnings, then explicitly submit for certification/publication.
Store customers receive the update through Microsoft Store, not the GitHub EXE.

The online GitHub chooser downloads only the selected Student or Teacher payload.
The single combined APPX contains both workspaces; selecting a welcome-page role
does not reduce that Store download or permanently restrict teacher tools outside
an active exam. Store package installation does not run the EXE download chooser.

Reference: https://learn.microsoft.com/en-us/windows/apps/publish/package-flights
