# Microsoft Store Additional Testing Information

LockedScreen is a full-trust desktop exam application with native Windows helpers.
This package contains teacher authoring and student examination views. Teacher
Google sign-in uses the system browser and publisher-hosted OAuth; school-specific
Google credentials are optional, not required for the default connection.

Use a supervised test device with a single display and close other work first.
Before starting any test, set and securely record a non-default invigilator exit
PIN. Import an exported practice package or use a short locally created test exam.
An exported package's exit PIN belongs to its exporting teacher.

During an active exam the application enables native keyboard filtering and kiosk
window restrictions. Teacher/settings/import views, external applications, browser
launches, screenshots and changes to kiosk/navigation controls are blocked. The
exam must not start if its native keyboard filter cannot confirm readiness. Do
not end the app from Task Manager as a normal test exit.

To leave, choose **Invigilator unlock**, enter the configured PIN, and choose
**Unlock session** or **Release student**. Blank/incorrect PINs must not release
the exam, including after submission. Correct release restores normal desktop and
keyboard behavior. Teacher configuration and normal app close work outside exams.

For Google Classroom, connect a teacher's Google account before starting an exam.
Posting returns the Classroom assignment ID. Student Google turn-in requires a
saved submission and invigilator-approved release before the system browser opens.
Google account consent and school Workspace app policies still apply. Across-PC
automatic grade publication requires the configured authenticated grade bridge.

Native helpers/.NET/Electron include process-launch APIs used by the full-trust
application and companion. Final WACK passed all 13 required tests, with one
optional "Blocked executables" failure for process-launch APIs/executable-name
references in the application, Chromium and .NET runtime. See the validation
record for details; this is disclosed for review, not treated as a policy waiver.
A normal desktop app cannot promise suppression of Windows secure-attention actions such
as Ctrl+Alt+Delete on unmanaged Home/Pro devices. Stronger school deployments use
managed kiosk and Keyboard Filter policy on supported Windows editions. The app
does not silently change those Windows security or accessibility settings.
