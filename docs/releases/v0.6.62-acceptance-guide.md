# 0.6.62 Supervised Acceptance

Use a spare/test PC, no live student exam, and keep the invigilator present. Know
the exit PIN before starting. Use a unique PIN, not the shipped example/default.
An exported package uses the PIN from the exporting teacher, not the receiving PC.

## Candidates

- Store upload: `apps/desktop/dist-store/LockedScreen-Store-0.6.62-x64.appx`.
- Isolated desktop shortcut: `tmp/LockedScreen-0.6.62-Test.lnk`. This exercises the
  same unpacked application/native files but not Store package identity/installation.
- GitHub chooser: `apps/desktop/dist-editions/web/LockedScreen-Setup-0.6.62-x64.exe`.
  Test role payload downloads only after corresponding release assets are published.
- For a signed Store installation, use a private Partner Center package flight.
  Do not add a self-signed certificate or uninstall the production app just to test.

## Before Starting

1. Create/import a short practice exam. Set a unique invigilator PIN, export a new
   package, and record that PIN securely. Keep any exam start/access password separate.
2. Disconnect additional displays. Close other work and confirm native diagnostics
   respond. Test an exported package on a separate Student installation as well as
   Student view in the combined Store candidate.
3. Teacher Google connection occurs before the exam. Confirm normal Google sign-in,
   course listing, posting, returned assignment ID and package export still work.
   Never request an external browser while answering an active exam.
4. While a sign-in/import/export is still pending, try starting a practice exam.
   Startup must wait/refuse until that operation finishes or is canceled; a pending
   browser or file dialog must never appear after exam startup.

For hosted-link exams, the exam URL must work without opening Google account
sign-in inside the embedded browser. Teacher OAuth does not sign that browser into
Google Forms. Use a native practice exam for the Classroom grade test; do not add
an external-browser exception during an exam to work around embedded sign-in.

## Active Exam

1. Questions must not appear until native startup succeeds. If native helpers are
   unavailable, the exam must refuse to start, with no insecure fallback.
   Hold either Windows key before startup: startup must refuse until it is released.
2. With a practice exam running, have the invigilator test Alt+Tab, Alt+Shift+Tab,
   Alt+Esc, Alt+F4, Alt+Space, Ctrl+Esc, Ctrl+Shift+Esc, Windows, Windows+Tab,
   Windows+D/E/R/L, Ctrl+Tab, Ctrl+L/N/O/R/W, browser-navigation keys, F11/F12 and
   Print Screen. Repeat with the right-side modifier keys and held/repeated keys.
3. Confirm the exam remains visible, focus is recovered, the taskbar is inaccessible,
   and normal answers, typing, Tab/Shift+Tab field navigation and exam buttons work.
   Test mouse/touch edges, virtual desktops, accessibility/IME surfaces and the actual
   keyboard layout used by students. Reserved Windows actions are a separate managed
   deployment test, not something an ordinary app can guarantee to suppress.
4. Attempt switching app views, opening another exam/package, close-window actions,
   external tools, settings or help links. None may leave or weaken the active exam.
   Unsaved answers must survive blocked navigation attempts.
5. Test missing/wrong invigilator PINs before and after submission. The app must remain
   locked. A valid PIN must release it, restoring normal taskbar, keyboard and window
   behavior. If native protection fails, the exam must pause, not continue unlocked.

## Submission And Google

1. Submit a known-score practice test. Verify local answers and grade are recorded.
   Submission alone must not allow the student to leave the exam.
2. Attempt LMS turn-in with an empty/wrong PIN: no release or external browser.
3. Enter the correct PIN: the exam is intentionally released, then Google sign-in
   may open in the normal browser. This is after examination, not a browser exception
   during the locked exam. Do not allow a student to resume an unsubmitted exam from
   an unrestricted Google window.
4. Verify the Classroom attachment, assignment ID and expected student grade. Across
   different PCs, automatic teacher-grade delivery still requires the configured
   authenticated grade-sync bridge; hosted OAuth alone is not a grade-sync bridge.
5. Reopen the app and start another short practice exam. Confirm lockdown starts
   fresh and the prior submission cannot authorize release of the new session.

Record Windows edition/build, installation source, keyboard layout, each result,
correct-PIN recovery, Google/grade results and any failure before Store submission.
