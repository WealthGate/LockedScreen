signed-in Google Forms remains unsupported in the embedded browser on unmanaged

## WACK

The fresh run completed against the exact APPX above using WACK 10.0.26100.7705
on Windows 11 Home 10.0.26300.0. Exit 0; overall PASS; partial run FALSE.

- Required tests: 13 passed, zero failed.
- Optional tests: 10 passed, one failed: **Blocked executables**.

The optional finding includes process-launch references in Electron/native/.NET
payloads, including CreateProcessW, ShellExecuteW and System.Diagnostics.Process.Start.
It also includes executable-name references. These findings are disclosed for
Partner Center review, not treated as Store-policy waivers.

The analyzer recorded 238 `FailedToLoad` entries for .NET assemblies, including
CoreLib reference/type-loading mismatches. Required metadata checks still passed;
this is not clean static inspection of every managed assembly. WACK is package
compatibility testing, not Microsoft certification or proof of live filtering.

`running: false`. The packaged Client executed but its coordinator connection was
refused (exit 1). No coordinator was started or stopped for this check, and no hooks
were activated. Live companion readiness/enforcement therefore remains a supervised
acceptance requirement, not a passed runtime health check for this build session.

contains machine inventory. No older version's result was reused.

## Remaining Acceptance

Follow `v0.6.65-acceptance-guide.md` on supervised target PCs and a signed private
Store flight. Real Google authorization, Classroom report delivery, provider marks,
native grade passback, actual display scale, switching restrictions and wrong/right
PIN recovery still require device testing. Classroom student authorization alone
does not authorize teacher grade writes or establish a Google Forms website session.

Keep Google Forms' one-response restriction enabled. Signed-in Forms is not supported
inside this app's embedded browser; no browser spoofing, cookie transfer or mid-exam
unrestricted browser exception was added. A separate supported-browser exam
deployment is required before claiming that workflow works on unmanaged Windows Home.

Unmanaged Home/Pro cannot guarantee suppression of reserved secure-attention keys.
Privileged tampering, multiple users, touch/IME/accessibility and managed Windows
kiosk/Keyboard Filter deployments require their own school validation. Do not treat
these automated checks as proof that every PC escape route is impossible.
