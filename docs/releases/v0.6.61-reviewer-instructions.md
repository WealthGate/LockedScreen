# LockedScreen 0.6.61: Additional Testing Information

LockedScreen is an Electron/Win32 examination app. Its runFullTrust capability is
required for the desktop executable and bundled Windows lockdown helpers. The helpers
enforce restrictions only for a supervised exam session and release them on authorized
invigilator exit. The app is not represented as a substitute for all Windows OS kiosk policies.

1. Launch the app and choose Teacher for the full authoring workspace. A teacher can
   prepare and take local practice examinations without Google sign-in. Student role
   is for opening teacher-supplied .lscp examination packages and taking exams.
2. On a fresh installation the administrative and invigilator PIN defaults are 2468.
   These are practice defaults and should be changed for production deployment. A teacher
   may set a separate exam start code under Student access; opening an exported file
   imports it but does not bypass that code.
3. Create or import a short practice exam, save its package, set an exam start code,
   and export the .lscp file. Open it in Student role, enter the start code, and complete
   the exam. Verify that answers and score are saved in Results on the teacher workspace.
4. With native lockdown available and enabled, test application switching and prohibited
   shortcuts during the session. Submit the exam and confirm the session remains locked.
   An incorrect or missing invigilator PIN must not release the session or launch Google.
   A correct invigilator PIN must restore normal desktop interaction.
5. Google integration is optional. New installations default to the publisher-managed
   hosted connection at https://auth.whsdominica.com. Teachers choose Connect Google
   Classroom, authenticate in Google's system-browser page, and approve the permissions.
   A Google account with a test Classroom class and teacher permissions is needed for
   this optional test. There is no shared reviewer Google account and no Google password,
   publisher Web client secret, or teacher token bundled in the package.
6. After connecting, load a practice class, post a package as an assignment, and confirm
   the returned assignment ID is stored in the package. Verify the attachment in Classroom.
   For publisher-managed student turn-in, enter the invigilator release PIN after the local
   submission is saved. This intentionally ends lockdown before opening the external browser
   for the student's Google sign-in. Google is never launched automatically during the exam.
7. A school Workspace policy may require the administrator to allow the publisher's OAuth
   app. Optional School-managed Desktop OAuth remains available to administrators; it is
   not required for the default publisher-managed connection.
8. On a different student PC, teacher-authorized automatic grade writing requires a separately
   configured authenticated grade-sync bridge. Posting a package alone does not configure
   such a bridge. Local results and student Classroom turn-in can be checked independently.
9. Updates for this APPX are managed by Microsoft Store. The app does not install a GitHub
   executable over a Store-managed installation.

Complete a real Google connection and supervised lockdown/release acceptance test before
submitting this candidate. A ready service health endpoint and a WACK pass are not evidence
that a real user's Google consent or every school's Windows restrictions have passed.
