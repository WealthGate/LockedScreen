# 0.6.64 Supervised Retest

Use a spare device, one display, no live examination, and an invigilator who knows
the unique exit PIN. Do not test normal recovery by terminating the app forcibly.

- Local test shortcut: `tmp/LockedScreen-0.6.64-Test.lnk`.
- Store candidate: `apps/desktop/dist-store/LockedScreen-Store-0.6.64-x64.appx`.
- Online installer: `apps/desktop/dist-editions/web/LockedScreen-Setup-0.6.64-x64.exe`.

The isolated shortcut uses the Store candidate's unpacked application/native files,
without replacing the installed Store app. It does not test Store signing or package
installation. Use a private Store flight for that final signed-device test.

## Prepare

1. Confirm version 0.6.64 and successful native diagnostics. In Teacher view,
   connect the teacher's Google account normally; no publisher OAuth JSON is needed.
2. Create a short known-score native practice exam. Post to the correct Classroom
   class, confirm its saved assignment ID, and set assignment points in Classroom.
3. Enable student LMS turn-in in the package. Set and securely record a unique
   invigilator exit PIN; set a separate exam access password if required. Save and
   export a fresh package. Imported packages use the exporting teacher's exit PIN.
4. On a separate Student PC, import that package. Use the enrolled student's school
   Google account, not the teacher account. Confirm the school's grade bridge if
   automatic grades across separate PCs are required.

## Sign-In And Exam

1. Choose the exam and enter its start password if required. Google sign-in opens
   before lockdown begins. While sign-in is pending, no exam questions may appear.
2. Cancel sign-in once: exam startup must fail, not show questions or fall back to
   an unlocked exam. Return to the exam list and try again.
   If a separate secure-desktop startup fails before any questions appear, close
   that failed startup window normally, then retry from the original app window.
3. Complete Google sign-in with the correct enrolled student account. Questions
   must appear only after native readiness and full display coverage are confirmed.
4. Check all physical screen edges, including the device's real 125%/150% Windows
   scaling if used. No title bar, desktop, taskbar or resize border may be exposed.
5. With supervision test Alt+Tab/Esc/F4/Space, Ctrl+Esc/Shift+Esc, Windows and
   Windows+Tab/D/E/R/L, browser shortcuts, F11/F12 and Print Screen. Also test
   right-side modifiers, held keys, normal typing and Tab navigation. App view
   changes, other packages, external tools and browser launches must stay blocked.
6. A protection failure must pause the exam, not continue unlocked. Reserved
   secure-attention actions on unmanaged Home/Pro require separate managed Windows
   policy validation; an ordinary app cannot guarantee complete suppression.

## Submit And Exit

1. Click Submit once. The local answers/score must be saved first, followed by
   automatic LMS delivery. No browser or additional PIN field should appear.
2. Verify Classroom receives the correct student's report under the correct
   assignment. Check grade status separately from attachment/turn-in status.
3. On a teacher-authorized test PC, verify grade scaling (50% becomes 10/20 on a
   20-point assignment). On separate Student PCs, verify the configured teacher
   grade bridge. Student sign-in alone cannot write teacher grades.
4. Test a controlled delivery/network failure: the saved result remains available
   and the exam stays locked. Retry should not open a browser or duplicate an
   already turned-in report. Expired/revoked authorization must not unlock the PC.
5. Click Invigilator unlock. Blank/wrong PINs must keep the exam locked, even if
   delivery succeeded. The correct PIN releases it, restores ordinary keyboard,
   desktop and window behavior, and does not trigger another Google sign-in.
6. Start a second exam/student session and repeat. It must obtain fresh student
   authorization before lockdown; the first student's authorization cannot release
   or submit another active session.

Repeat on the actual signed Store flight. Record Windows edition, display scale,
installation source, native shortcut results, both PIN outcomes, real Google grant,
assignment ID, attachment and expected grade before general Store publication.

An older Teacher/Admin help sentence still describes post-submit sign-in. Follow
the pre-exam sequence above for 0.6.64; the runtime no longer uses that old sequence.
